**What you'll get:** A real desktop app for your AI quota dashboard — a window that shows every provider's remaining usage with live countdowns and trend lines, lets you hide the ones you don't care about, and sits in your menubar/tray so it can warn you before something runs dry. Crucially, the providers that today need you to hand-copy browser cookies into JSON files instead get a "Sign in" button: the app opens the provider's own login page in a private window, and once you're signed in it writes the credentials where the tool already expects them.

**Why this approach:** The app runs your existing quota engine directly instead of reimplementing or shelling out to it, so there's exactly one place where provider logic lives and the terminal version keeps working unchanged. And because the app is Chromium-based, in-app sign-in is a natural fit — no more DevTools cookie archaeology.

**What it will NOT do:** It won't change how the current terminal command or live dashboard behave. It won't move your credentials into a new format or a system keychain — they stay in the same files, just written for you. It won't ship signed/auto-updating installers yet (that needs a paid Apple developer identity), so the first builds are ones you build or open manually.

**Effort:** Large
**Risk:** Medium — the main unknowns are outside our control: some provider login pages refuse to run inside an embedded browser, and session cookies expire, so the app must detect and re-prompt gracefully. There's also a documented drift risk: one piece of display logic has to be copied from the terminal dashboard because it isn't shared code.
**Decisions to sanity-check:** Electron (bigger download, but zero duplicated logic); the app lives in a `desktop/` folder inside this same repo; desktop-only settings go in their own small config file rather than your existing `mystatus.json`; credentials stay as plaintext JSON files exactly as the plugin reads them today.

## Scope

## Verification strategy
> Zero human intervention - all verification is agent-executed.
- Test decision: **tests-after** — repo has no test infrastructure today; the desktop app introduces its own harness. Framework: Vitest for main-process units (credential-file writers, capture extractors, tier classification, notification decisions, IPC handlers with mocked core) + Playwright's Electron driver (`_electron.launch`) for end-to-end window/IPC flows.
- **No real provider accounts are ever required.** Two seams make this work: (1) unit/integration — set `process.env.HOME` (and `USERPROFILE` on Windows) to a tmp dir, seed fake credential files, and `vi.stubGlobal('fetch', fixtureFetch)`; the core calls bare global `fetch` with no cached reference, so stubbing works. (2) E2E — `_electron.launch({ env: { ...process.env, HOME: tmpDir, USERPROFILE: tmpDir } })` then `electronApp.evaluate(() => { globalThis.fetch = fixtureFetch })` before polling starts.
- **MANDATORY SAFETY GATE:** every test that can touch disk MUST run with `HOME`/`USERPROFILE` redirected to a tmp dir. The core's `configFile()` hardcodes `homedir()/.config/opencode` and ignores `OPENCODE_CONFIG_DIR` (plugin/mystatus.ts:6673-6678), so an unredirected test would overwrite the developer's real config, cache, history, and credential files. Any todo whose test writes files without this redirection FAILS review.
- **Features Playwright cannot assert** get explicit alternate gates: tray (unit-test the menu template + icon-variant selector with `vi.mock('electron')`), notifications (unit-test the pure crossing/cooldown decision function), auto-update (assert generated `electron-builder` config + `latest.yml` presence; never assert a live update), code signing (a `codesign --verify --deep --strict` + `spctl -a -t exec` script that is SKIPPED with a logged reason when no signing identity is present).
